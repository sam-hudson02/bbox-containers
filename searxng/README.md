# searxng

Metasearch front end. Queries go out to other engines and come back with no
account, no tracking and no ads.

| | |
|---|---|
| Web UI | `http://192.168.1.152:8081` |
| Upstream | https://docs.searxng.org/admin/installation-docker.html |
| Deploy | `ansible-playbook site.yml --limit bbox --tags stacks -e stack=searxng` |

Two containers: SearXNG itself and a Valkey for its cache and limiter.

## First deploy

The generated settings file already on the box is owned by uid 977, so the
deploy cannot replace it. Clear it first, once:

```bash
ssh bbox 'sudo rm /home/sam/containers/searxng/config/settings.yml'
```

Then fill in `.env.example` as `.env`, encrypt it to `.enc.env`, shred the
plaintext, and deploy.

## Settings

`settings.yml` in this repo, deployed to `config/settings.yml` on the box,
which is what the container mounts. Edit it here and redeploy; a copy edited on
the box is overwritten by the next deploy.

It is `use_default_settings: true` plus a short diff, so engines, languages and
everything else not named follow upstream's defaults. The base URL, the
limiter, the Valkey URL and `secret_key` are not in it: those come from the
compose file and `.env`, and an environment variable wins over this file.

The container generates its own settings only when the file is missing, so a
deployed one stops that happening.

PriceBuddy's product research asks this instance for JSON, and SearXNG answers
a format that is not listed with a 403, which is what `search.formats` is for.
Keep `html` in that list or the web UI stops working, and leave the limiter off:
it treats an API call as a bot and 403s it just the same.

## Secrets

One: `SEARXNG_SECRET`, which signs the session cookie. `.env.example` says how
to generate it. Changing it only discards saved preferences.

## State

Nothing. `config/settings.yml` is deployed from this repo, and `cache/` and
`valkey/` are both regenerated by use. No backup job.

## Exposure

Port 8081, plain HTTP, no authentication, on trusted. Anyone on the house
network can search through it, which is the intended use. It is not forwarded
and should not be: a public SearXNG attracts bots, which is what the limiter
and `SEARXNG_PUBLIC_INSTANCE` exist for.

Search queries leave the house to the upstream engines, as they would from any
browser. Nothing is logged here beyond the container's own request log.
