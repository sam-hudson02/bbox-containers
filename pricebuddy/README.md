# pricebuddy

Price tracker for the shopping list in the notes vault. Products, each with one
or more shop URLs, price history, and notifications when a price drops.

| | |
|---|---|
| Web UI | `http://192.168.1.152:8080` |
| Upstream | https://github.com/jez500/pricebuddy, docs at https://pricebuddy.jez.me |
| Deploy | `ansible-playbook site.yml --limit bbox --tags stacks -e stack=pricebuddy` |

Three containers: the app (Laravel, with its own cron for scheduled scrapes),
MySQL, and a SeleniumBase scraper for shops that render prices with JavaScript.

## First deploy

1. Fill in `.env.example` as `.env`, encrypt it to `.enc.env`, shred the
   plaintext. The comments in the file say how to generate each value.
2. Deploy. The first start runs migrations and seeds the login from
   `APP_USER_EMAIL` and `APP_USER_PASSWORD`, which takes a minute.
3. Settings: set the locale to `en_GB` and currency to `GBP`, and set up a
   notification channel.
4. User menu, API tokens: create one for the vault sync if it is being used.

## APP_KEY

Set in `.enc.env`, not generated by the container. Upstream mounts a `.env`
into the app so its first boot can write a key there, but this stack's `.env`
is rewritten from SOPS on every deploy, which would throw a generated key away.
Losing the key breaks everything the app has encrypted with it.

## State

`./mysql` is the data: products, URLs, stores and the whole price history.
`./storage` is logs, sessions and caches.

A live MySQL data directory is not a backup. A job for this wants a
`mysqldump` in its `pre` step, written beside the stack and rsynced, the same
shape as the Pi's postgres job.

## Exposure

Port 8080 is plain HTTP behind the app's own login, on trusted only. The API
uses bearer tokens with per-token permissions.

The start script prints its environment, so the database password is in
`docker logs pricebuddy`.
